# APP-004 — Москва и МО
## VISUAL / UI ТЗ — v0.7
**Статус:** Desktop Dashboard и Search / Results утверждены; остальные экраны в работе  
**Дата:** 25.09.2026  
**APP-ID:** APP-004

# 1. Цель

Не переносить Excel как есть. Пользователь должен быстро решать:
1. куда сходить из проверенных вариантов;
2. что нового исследовать;
3. какие актуальные события есть в ближайшие 14 дней;
4. что уже было посещено и сколько это стоило.

# 2. Не показывать внутренности

Обычный UI не показывает ResearchID / ExperienceID / EventID / VisitID / TxID, QA/APP коды, PASS1/PASS2, SelectionKey/Rank, lifecycle-коды, source confidence, freshness, retry/scheduler/parser/ingestion и служебные Excel-колонки.

# 3. Навигация

Три верхнеуровневых раздела:
- **Главная**
- **История**
- **Настройки**

Любимые, Research и Events по возможности объединяются на Главной. Полные списки открываются через «Показать все».

# 4. Главная

Верхняя зона:
- единый поиск;
- быстрые фильтры;
- бюджет месяца;
- переключатель источников: Любимые / Research / События.

**Визуальное направление текущего согласованного макета принять за основу:** светлый плотный personal dashboard, где слева «Куда сходить» + увеличенный Research, по центру Events, справа бюджет + расширенная погода.

Источник: Favorite / Experience.

Компактно показывать:
- **картинку / thumbnail**;
- название;
- оценку;
- главное состояние;
- район / сектор;
- день / вечер;
- один / вместе;
- стоимость;
- **длительность на месте**;
- **время дороги**;
- **полное время**;
- короткую причину «почему подходит сейчас».

Изображение — компактное, одинакового формата во всех строках; при отсутствии изображения показывать аккуратный fallback.

5–8 вариантов + «Все любимые».

## Исследовать новое

Источник: Research.

Показывать:
- **картинку / thumbnail**;
- название;
- класс / подтип;
- главное состояние;
- день / вечер;
- улица / помещение;
- один / вместе;
- Москва / МО;
- район;
- первый тест;
- **длительность на месте**;
- **время дороги**;
- **полное время**;
- цена;

**Research-блок увеличить.** На desktop он должен занимать заметно больше места, чем в первом макете: ориентир — 5–6 видимых исследований либо аналогичный полезный объём. Research не должен выглядеть второстепенной припиской.

Не показывать технические PASS2/Rank/SelectionKey.

## События — 14 дней

Обязательный блок. По умолчанию только период **сегодня → +14 дней**, ближайшее сверху.

Карточка:
- дата;
- время начала / окончания;
- **картинка / thumbnail**;
- название;
- место / район / сектор;
- тип;
- главное состояние;
- один / вместе;
- бесплатно / цена;
- обычная и текущая цена;
- скидка;
- доступность;
- корректный CTA: купить / оформить / зарегистрироваться / забронировать.

После 14 дней — «Показать дальше».

# 5. Единый поиск

Один поиск по:
- Любимым;
- Research;
- Events LIVE.

Каждый источник можно отключить.

Поиск учитывает название, класс, подтип, район/город, сектор, Москва/МО, главное состояние, эмоции, **атрибуты атмосферы**, день/вечер, улица/помещение, один/вместе, цену, время, дорогу, дату события, описание, комментарии и маршрут.

Для **Favorite / «Куда сходить»** и **Research / «Исследовать»** поиск и фильтрация по эмоциям и атмосфере являются обязательными и работают одинаково.

Примеры атмосферных признаков, если они присутствуют в данных: вода, простор, тишина/спокойствие, зелень, вечерние огни/подсветка, музыка, фонтаны, архитектурная выразительность. Использовать уже существующую модель атрибутов, а не создавать вторую параллельную систему тегов.

# 6. Полная выдача

Таблица/grid со сортировкой кликом.

Текст: А→Я / Я→А.  
Числа: меньше→больше / больше→меньше.  
Даты: раньше→позже / позже→раньше.

Сортируемые минимум:
- название;
- источник;
- дата;
- район / город;
- сектор;
- класс;
- цена;
- цена с дорогой;
- время дороги;
- полное время;
- оценка;
- главное состояние;
- **каждая числовая эмоциональная шкала**, если она включена в выдачу;
- другие числовые пользовательские показатели, которые реально присутствуют в данных.

Эмоциональные поля и атмосферные атрибуты должны быть доступны не только для отображения, но и для реальной работы с выдачей:
- эмоции / состояния — фильтр + поиск + сортировка по баллу, если поле числовое;
- атмосферные теги — фильтр + поиск;
- текстовые атрибуты — А→Я / Я→А там, где такая сортировка имеет смысл.

Требование относится как минимум к Favorite и Research. Для Events — только к тем эмоциональным/атмосферным полям, которые действительно заполнены данными.

# 10. Погода

**Блок «Быстрый выбор» из первого макета убрать полностью.**

Его место в правой колонке занимает расширенный погодный модуль.

## Сегодня

Показывать четыре временных периода:
- утро;
- день;
- вечер;
- ночь.

Для каждого:
- температура;
- иконка / состояние;
- осадки или вероятность осадков, если источник их предоставляет.

## Неделя

Ниже показывать краткий прогноз на **7 дней**:
- день недели / дата;
- иконка;
- минимум / максимум температуры;
- краткое состояние / осадки.

Погода должна быть реально читаемой и полезной для решения «идти на улицу или выбрать помещение», а не декоративной плашкой.

В текущей версии достаточно погоды по Москве как базовой точке. Архитектура не должна закрывать возможность позже учитывать МО / выбранный район.

# 13. Lifecycle в пользовательском языке

Пользователь может:
- открыть;
- запланировать;
- подтвердить «Я сходил»;
- заполнить расходы;
- оставить впечатление;
- отказаться.

Правила:
- прошедшее Event само не создаёт Visit;
- Research не становится Favorite без реального положительного Visit;
- отрицательный Visit сохраняется;
- Favorite evidence не удаляется физически;
- текущая Favorite-цена не переписывает старые Visits.

# 15. Визуальное направление

Современный personal dashboard, не Excel в браузере:
- светлая база;
- высокая читаемость;
- умеренная плотность;
- ясная сетка;
- компактные карточки;
- таблица только там, где она удобнее;
- цвет кодирует смысл;
- минимум декоративного шума.

Favorite / Research / Event визуально различаются, но остаются частью одной системы.

Не добавлять обязательный дополнительный «главный тезис»/промо-плашку в каждую карточку Favorite. Текущая информационная плотность сохраняется; акцент делается на нормальной сортировке, поиске и фильтрации.
